# ADR-0024 — GitHub: conexão validada por clone, commit por tarefa e push restrito com prova por ref

- **Estado:** ACEITA · **Ticket:** [T15-01](../NEW%20MVP/03-BACKLOG.md#t15-01) · **Épico:** E15 · **Relacionadas:** [ADR-0005](0005-autenticacao-sessoes-e-cofre-de-conexoes.md), [ADR-0008](0008-sandbox-por-feature-em-containers.md), [ADR-0018](0018-ledger-de-efeitos-externos.md), [ADR-0023](0023-checkpoints-integros.md)

## Decisão
1. **Duas interfaces.** `Connector` (leitura: `Check`, `Clone`, `RemoteRef`) nunca altera o remoto. `Effects` (escrita: `Push`) só existe pelo **ledger de efeitos**. O git roda no **host do worker** (o sandbox não tem rede nem credencial); o conteúdo do workspace chega pelo manifesto do checkpoint.
2. **Conexão valida o clone de verdade:** `Check` confere (ls-remote) que o ramo base existe, **clona** (`--bare --single-branch`) e compara o clone com a ref remota. Com a API do GitHub (`GET /repos/{o}/{r}` e `/branches/{base}`) também exige permissão de push, repositório não arquivado e **ramo base protegido**; sem API (ou com a API fora do ar), esses itens aparecem em `unverified`, nunca como aprovados.
3. **Credencial só pelo cofre:** `security.Secret` entra como cabeçalho HTTP na **variável de ambiente** do processo git (`GIT_CONFIG_COUNT/KEY/VALUE`), nunca em argumento, URL, `.git/config` ou log; erros do git são classificados (auth, não encontrado, recusado, timeout) e o texto vai **redigido** (token e base64 do cabeçalho). Só `https` (e `file://` em teste); `GIT_ALLOW_PROTOCOL` bloqueia `ext::` e afins; `HOME` temporário, sem config global/sistema, `core.hooksPath=/dev/null`, `credential.helper` vazio, sem prompt.
4. **Branch por feature:** `lf/f-<feature>-a<tentativa>`, estável entre repetições. **Push restrito (`PushRequest.Guard`), antes de qualquer comando git:** só a branch exata da feature/tentativa; nunca a base; refspec montado pelo código (`<sha>:refs/heads/<branch>`), sem `+`, exclusão, tags, nome livre ou SHA que não seja hexadecimal completo. Pedido recusado nem vira intenção no ledger.
5. **Commit por tarefa validada:** `Workdir.Commit` exige checks **aprovados** (nomes + hash do relatório), chave de tarefa válida e pai conhecido; monta o commit com **`git fast-import`** a partir do manifesto (sem extrair arquivo no host: sem travessia nem link simbólico), preserva modo executável e links (como links, sem segui-los), recusa componentes `.git`, caracteres de controle e conteúdo igual ao do pai. A mensagem leva trailers `Lf-Task`, `Lf-Checks`, `Lf-Checks-Report` e `Lf-Tree`; `ReadTrailers`/`Matches` provam que o commit corresponde à tarefa e aos checks. Data e identidade fixas ⇒ **o mesmo pedido gera o mesmo SHA**, o que torna a prova do push inequívoca.
6. **Push como efeito:** chave de negócio `<projeto>:<feature>:<tentativa>:push:<branch>:<sha16>`. Prova por ref (`ls-remote`): ref no SHA esperado ⇒ confirmado; ausente ⇒ repetir é seguro; **à frente** (o nosso commit é ancestral da ponta) ⇒ confirmado, com a ponta atual na prova; **atrás** ⇒ ausente (avançar é seguro); **divergente** ou consulta ilegível ⇒ inconclusivo (bloqueio com evidência, a fábrica **não** sobrescreve o que não é dela). Recusa do remoto (rejeitado, sem permissão) é "sem efeito"; timeout deixa o resultado desconhecido e a prova decide.
7. **Mudança em `.github/`** (workflows) exige aprovação explícita (`AllowWorkflows`), pois altera o que roda com segredos do repositório.

## Limites
- **GitHub real: NOT_RUN.** A prova usa o `git` real contra um repositório bare local (`file://`) e um servidor de mentira para a API REST. Permissão efetiva de push, proteção real do ramo base (e a recusa de push direto pelo servidor) e rate limits só se confirmam numa conta real.
- `unverified` no relatório quando não há API; o preflight completo pede a API.
- Clone completo por padrão (`Depth` opcional); repositórios muito grandes podem exigir clone raso ou parcial.
- Criar/atualizar PR e confirmar merge são do T15-02/T15-03; o verificador de merge real (T06-03) continua sem adaptador.
- Execução do git no host do worker: o `git` precisa existir lá (a imagem do worker ainda não o inclui — decisão de implantação pendente).
